# Database
PostgreSQL database running in Docker.

## Build & Run
```bash
docker build -t overseas_db . 
docker run --name my-database -p 5432:5432 overseas_db
```

## Connect
```bash
psql -h localhost -U myuser -p 5432 -d overseas_db
```
**Credentials**
 User :     `myuser`   
 Password : `123`      
 
## Schema, triggers and seed data
The database starts **empty**: the dump is no longer loaded at container init.
The backend bootstraps everything on startup via `flask db upgrade`
(see `backend/migrations/versions/`):

1. `33e4600ce890_initial_schema.py` — all tables, autogenerated from `backend/models.py`
2. `c8e4f5b62d15_seed_data.py` — demo dataset (users, institutions, exams, sample applications)
3. `b7f3d2a91c04_add_triggers.py` — all 11 trigger functions + triggers (runs after the
   seed on purpose, like pg_dump restore order: historical rows would trip the INSERT triggers)

To reset to a fresh state:
```bash
docker compose down -v && docker compose up --build
```

Schema or trigger changes go in a **new** migration at head — never edit an applied one.

`overseas.sql` is the legacy dump kept for reference; it is not used at runtime anymore.

## Dump (optional, for backups)
```bash
pg_dump -U myuser -h localhost -p 5432 -d overseas_db -f overseas.sql
```
